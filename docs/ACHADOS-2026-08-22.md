## Achado 1 — A SPA publicava 200 mas NÃO renderizava a calculadora

**Sintoma:** `https://camillanapoles.github.io/github-actions/llm-infra-planner/` dava
`200` + `<title>LLMcalc</title>` + bundle JS `200`, mas no browser só aparecia o **shell**
(navbar, footer, drawer de compare vazio). Sem VRAM, cloud cost, latência, GPU picker.

**Causa-raiz:** o `llm-infra-planner` usa `BrowserRouter` **sem `basename`**
(`examples/06-docker-to-actos/llm-infra-planner/src/App.tsx`). Foi construído para servir
à **raiz** (Docker + nginx); agora vive em `/github-actions/llm-infra-planner/`. O React
Router tenta fazer match da rota `/` contra esse path → **nenhuma rota faz match** → só o
shell renderiza.

**Prova (DOM render/jsdom):**
- URL `/` → calculadora completa (VRAM, Cloud, GPU, Model, Llama) ✅
- URL `/github-actions/llm-infra-planner/` (a live) → apenas shell ❌

**Fix:** `BrowserRouter basename={ROUTER_BASENAME}` com
`const ROUTER_BASENAME = '/github-actions/llm-infra-planner'` (`93a885a`).

## Achado 2 — Subpáginas do menu apontavam para a raiz do site

**Sintoma:** mesmo com o router a renderizar, os links do menu
(`Calculator`, `Compare`, `Reverse`, `Models`, `Hardware`, `Guides`) e
`methodology` (footer) apontavam para `https://camillanapoles.github.io/compare`,
`/models`, … — **a raiz do site**, não a subapp.

**Causa:** `TopBar.tsx` e `Footer.tsx` usavam `<a href="/compare">` (e afins) — `<a>`
ignora o basename do router.

**Prova:** `fetch_page` na live listava links para `https://camillanapoles.github.io/`
(raiz); após o fix, todos os hrefs internos saem
`/github-actions/llm-infra-planner/{compare,reverse,models,hardware,guides}`.

**Fix:** substituir `<a href>` por `<Link to>` do React Router (honra o basename) em
`TopBar.tsx` (desktop + mobile) e `Footer.tsx`; rebuild `webpage/` (`index-ezmrC6cc.js`).
**Commit `29e2bef`** — **já em `main`** (confirmado via `git ls-remote`).

## Achado 3 — KERNEL EM BRANCH ≠ KERNEL DEPLOYADO (o achado central)

**A pergunta do usuário:** *"construí o kernel numa branch — pode ter a ver? Construído
com workflow harness, comando `npm run cdn:export`"*.

**Resposta: SIM.** Provado por execução, não por leitura.

### O que existe
| Fonte | `src/cli/cdn-export.ts` | `webpage/llm-infra-planner/` |
|---|---|---|
| `main` (`93a885a`) | ✅ tem o merge do `webpage/` | ✅ **SIM** |
| branch de kernel antiga `arena/01a01e33-github-actions` (`3b269bd`) | ⚠️ tem, **SEM** o merge | ❌ **NÃO** |
| `actos/fs` (`54f549f`) | n/a (só objectos) | ❌ **NÃO** |

### Prova por execução (dois worktrees, mesmo comando `npm run cdn:export`, `ACTOS_GITFS=0`)
```
# kernel da branch antiga (3b269bd)
[cdn-public] n= 37
# NÃO imprime  "[cdn-public] webpage/ merged"
/tmp/old-cdn/llm-infra-planner → NÃO EXISTE ❌

# kernel de main (93a885a)
[cdn-public] n= 37
[cdn-public] webpage/ merged → /tmp/new-cdn
/tmp/new-cdn/llm-infra-planner/index.html → <title>LLMcalc</title> ✅
```
`diff -rq old new` → `Only in new: README.md, llm-infra-planner`.

**Conclusão:** o mesmo comando, com o kernel de uma branch sem o merge, **produz um CDN
sem a calculadora**. A página funciona hoje **só porque** `cdn-pages.yml` faz
`checkout ref: main`. Quem “monta o kernel numa branch” (via harness) não garante que o
workflow de produção o use — **o workflow executa o conteúdo da branch do seu checkout**.

### Porque é que o `actos/fs` NÃO é o problema
- `actos/fs` contém `agents/*`, `objects/*`, `cache/*`, `proc/*` — **não contém
  `webpage/`** nem o kernel.
- No `cdn-pages.yml`, `actos/fs` só é **lido** (`git fetch` + `hydrate`) para os
  objectos ACTOS na raiz do CDN; o site estático (`webpage/`) vem do **checkout de `main`**.
- `fs-sync.ts --push` (única escrita em `actos/fs`) **não faz parte** do `cdn-pages.yml`.

### O problema real no `gc.yml`
`gc.yml` fazia:
```yaml
- uses: actions/checkout@v6
  with:
    ref: arena/01a01e33-github-actions   # branch de kernel antiga (3b269bd)
```
Essa branch tem `cdn-export.ts` **sem** o merge de `webpage/` e **não tem** `webpage/`.
O GC só escreve `actos/fs`, mas é a mesma família de kernel desatualizada — uma
**bomba-relógio** para qualquer passo que exporte com ela.

**Correção preparada (ainda NÃO em `main`, ver Achado 4):**
```yaml
- uses: actions/checkout@v6
  with:
    ref: main          # kernel de produção, com o merge do webpage/
    fetch-depth: 0
```
Mais **guard-rail** no `cdn-pages.yml` (porque o `cdn:export` falha em silêncio):
```yaml
- name: Assert calculadora presente (webpage merge)
  run: |
    test -f .actos-cdn/llm-infra-planner/index.html \
      || { echo "::error::webpage/ não foi exportado — kernel do checkout sem merge"; exit 1; }
    grep -q '<title>LLMcalc</title>' .actos-cdn/llm-infra-planner/index.html \
      || { echo "::error::index.html da calculadora não é o LLMcalc"; exit 1; }
```
Asserção **testada**: passa com o artefacto certo e **falha** (exit 1) no cenário do bug.

## Achado 4 — Permissões do App da Arena (porque faltam 2 correções em `main`)

- `gh workflow run cdn-pages.yml` → **HTTP 403** (token REST sem `actions: write`).
- `git push` da branch da sessão → **rejeitado**:
  ```
  refusing to allow a GitHub App to create or update workflow
  `.github/workflows/cdn-pages.yml` without `workflows` permission
  ```
- `git push` de **código normal** (docs, `webpage/`, `src/`) → **funciona**.

Ou seja: **documentação e código podem ir para o repo; alterações em
`.github/workflows/*` precisam do humano** (permissão `workflows`).
Por isso o patch está guardado em [`docs/fixes/`](fixes/).
